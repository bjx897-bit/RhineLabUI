# 修改个人档案

[archives.json](archives.json) 是页面与 TXT 下载共用的数据。当前只保留“个人信息”分类和一份示例档案；张三、示例大学等内容均为占位示例。

## 替换为自己的资料

在 `records` 中修改以下四个字段即可，页面会一次展示全部内容，无需设置页签或研究记录：

| 字段       | 显示内容 | 当前示例         |
| ---------- | -------- | ---------------- |
| name       | 姓名     | 张三             |
| major      | 专业     | 计算机科学与技术 |
| school     | 学校     | 示例大学         |
| targetRole | 意向岗位 | 前端开发工程师   |

`title` 是中文档案标题，`en` 是英文标题，`category` 是所属分类，`id` 用于定位及下载文件名。以上字段均必填且不能只含空白。所有内容按纯文本显示，不支持 Markdown 或 HTML；引号按 JSON 规则写为 `\"`，换行写为 `\n`。

## 分类与档案数量

- `categories` 定义分类名称，`columns` 定义这些分类在资料库中的排列顺序；两者名称必须一致且不能重复。
- `records` 至少包含一份档案，每个分类至少有一份，数量不必相同。同分类的数组顺序决定档案顺序。
- 编号采用 `X-001` 至 `X-999`，不能重复。新增档案使用未占用的编号，已有档案可调整顺序，无需重新编号。
- 修改分类名时，同时更新 `categories`、`columns` 和各档案的 `category`。

## 更新与验证

1. 编辑 JSON 中的资料。
2. 执行 `npm run export:archives`，校验数据并更新 `public/archives/` 中的 TXT 文件。已删除档案对应的旧生成文件会一并清理；其他文件不受影响。校验失败时不会改动下载文件。
3. 执行 `npm run check:content` 和 `npm run build`，然后发布新的构建产物。将 JSON 与生成的 TXT 一起提交。
4. 使用 `npm run dev` 检查档案标题、正文和下载内容，尤其注意较长文字的换行。

开发启动和生产构建前都会自动校验并导出。开发服务器运行期间修改 JSON 会更新页面；TXT 下载需要再次执行 `npm run export:archives` 或重启开发服务器。
